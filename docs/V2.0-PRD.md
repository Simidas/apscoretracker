# AP Score Tracker — V2.0 产品需求文档

> 版本：V2.0  
> 日期：2026-06-26  
> 状态：开发准备稿，基础工程已启动  
> 当前代码基线：V1.1 local-first tracker  
> 开发目标：Clerk 登录 + Cloudflare D1 云端数据 + Stripe Pro 订阅  

---

## 0. 结论先行

V2.0 要把 AP Score Tracker 从“浏览器本地工具”升级为“有账号、有云端数据、有付费分层”的完整产品。

### V2.0 做什么

- 增加用户登录/注册
- 登录用户的数据保存到 Cloudflare D1
- 增加 Free / Pro 分层
- 增加 Stripe 订阅支付
- 增加账户页 `/account`
- 更新隐私政策、服务条款、Cookie/第三方服务说明

### V2.0 不做什么

- 不做教师班级版
- 不做 AI 作文评分
- 不做社交排行榜
- 不做移动端 Native App
- 不做多语言，仍以英文产品界面为主
- 不在 P0 承诺迁移现有 localStorage 历史数据
- 不在 P0 引入广告系统

### 关键产品决策

| 决策点 | V2.0 口径 |
|---|---|
| 未登录用户 | 可以访问 Landing、SEO、博客、隐私/条款；可以看 demo/试算；不能保存记录或查看历史 |
| 保存记录 | 必须登录 |
| 历史记录 | 登录后从 D1 读取 |
| V1 localStorage 数据 | P0 不自动迁移；保留 JSON import/export 作为用户自助迁移兜底 |
| 付费模式 | Free 免费层 + Pro 订阅 |
| 支付方案 | 目标为 Stripe Elements 内嵌订阅；Checkout 作为降风险备选 |
| 部署平台 | 继续使用 Cloudflare Workers + `@opennextjs/cloudflare` |

## 2. V2.0 目标与成功标准

### 2.1 产品目标

- 登录用户可以跨设备同步模考记录和目标分数。
- Free 用户能体验核心追踪价值，但有合理限制。
- Pro 用户获得无限记录、更多导出和高级报告能力。
- 支付成功后 Pro 权限自动生效。
- 订阅取消/失败/到期后权限能自动降级。

### 2.2 技术目标

- D1 schema 可迁移、可重复执行。
- API 路由统一鉴权，用户只能访问自己的数据。
- Stripe webhook 有签名校验和幂等处理。
- Cloudflare Workers 部署通过。
- 保持当前 V1.1 主要 UI 体验，不大改视觉系统。

### 2.3 成功标准

- 用户能完成 Google 或 Email 登录。
- 用户能保存、刷新、换浏览器后看到同一批记录。
- Free 限制准确触发，Pro 不受限制。
- Stripe 测试模式完整订阅流程通过。
- `/account` 能显示订阅状态、使用量、导出和删除入口。
- `npm run build` 与 `npx opennextjs-cloudflare build` 均通过。

## 3. 用户状态与权限

### 3.1 用户状态

| 状态 | 定义 | 允许行为 |
|---|---|---|
| Anonymous | 未登录访问者 | 访问公开页面、使用 demo/试算、点击登录 |
| Free | 已登录，未订阅 | 保存有限记录、设置目标分数、JSON 导出 |
| Pro | 已登录，有有效订阅 | 无限记录、高级导出、高级报告 |
| Past due | 订阅付款失败宽限期 | 暂保 Pro 权限或按 Stripe 状态策略限制 |
| Canceled | 订阅取消且周期结束 | 降级 Free，保留数据，只限制新增/高级功能 |

### 3.2 Free / Pro 权限

| 功能 | Anonymous | Free | Pro |
|---|---|---|---|
| 访问 Landing / SEO / Blog | 是 | 是 | 是 |
| 使用试算 demo | 是 | 是 | 是 |
| 保存记录 | 否 | 是，有限制 | 是，无限制 |
| 查看历史记录 | 否 | 是 | 是 |
| 设置目标分数 | 否 | 是 | 是 |
| 每科记录数 | 0 | 每科 10 条 | 不限 |
| 可追踪科目数 | 0 | 5 科 | 后续扩展后不限 |
| JSON 导出 | 否 | 是 | 是 |
| CSV 导出 | 否 | 否 | 是 |
| 打印报告 | 否 | 基础 | 高级 |
| 账户页 | 否 | 是 | 是 |

说明：当前代码实际只有 5 个 Tracker 科目，所以“Pro 无限科目”要等科目扩展后才有完整价值。V2.0 可以先把权限模型做好，但不要在 UI 中承诺尚未上线的科目数量。

## 5. 核心用户流程

### 5.1 登录流程

```text
用户点击 Sign In
  ↓
Clerk 登录/注册
  ↓
首次登录触发 user upsert
  ↓
返回 tracker 或 account
  ↓
前端调用 /api/me 获取 tier、usage、limits
```

验收：

- Google OAuth 成功。
- Email 登录成功。
- 刷新后会话保持。
- 登出后 `/account` 不可访问。
- 未登录保存记录时引导登录，不静默失败。

### 5.2 保存记录流程

```text
用户在 /tracker 输入分数
  ↓
前端复用现有 calculateTotalPercent / calculateApScore
  ↓
POST /api/records
  ↓
API 校验 Clerk session
  ↓
API 校验 Free/Pro limit
  ↓
D1 insert
  ↓
返回新记录
  ↓
前端刷新 history/chart/tips
```

验收：

- 登录用户保存后刷新仍在。
- 换浏览器登录同账号仍可看到。
- 数据只属于当前用户。
- Free 达到限制时返回明确错误码，前端弹 Upsell。

### 5.3 升级 Pro 流程

目标方案：Stripe Elements 内嵌订阅。

```text
用户点击 Upgrade
  ↓
POST /api/billing/subscribe
  ↓
服务端创建或复用 Stripe Customer
  ↓
服务端创建 Subscription，payment_behavior=default_incomplete
  ↓
返回 latest_invoice.payment_intent.client_secret
  ↓
前端 Stripe Elements confirmPayment
  ↓
Stripe webhook 更新 users.subscription_tier/status
  ↓
前端重新拉取 /api/me
  ↓
Pro 权限生效
```

降风险备选：使用 Stripe Checkout。

```text
用户点击 Upgrade
  ↓
POST /api/billing/subscribe
  ↓
返回 Stripe Checkout URL
  ↓
跳转支付
  ↓
Webhook 更新订阅
  ↓
返回 /account 或 /tracker?upgraded=1
```

产品偏好是 Elements，但如果开发/合规风险高，Checkout 可作为 V2.0 MVP 方案。

### 5.4 账户管理流程

`/account` 展示：

- 用户邮箱
- 当前 tier：Free / Pro / Past due
- 订阅周期结束时间
- 已使用科目数
- 已保存记录数
- JSON 导出
- Pro CSV 导出
- Manage Subscription
- Delete Account

## 6. 数据模型

### 6.1 当前前端模型

权威来源：`src/lib/tracker-data.ts`

```typescript
export type ExamRecord = {
  id: string;
  subjectId: string;
  date: string;
  mcqScore: number;
  frqScore: number;
  totalPercent: number;
  apScore: 1 | 2 | 3 | 4 | 5;
  topicScores: Record<string, number>;
  notes?: string;
};
```

V2 D1 schema 应直接对应当前字段，避免再使用旧文档里的 `subject`、`totalScore`、`breakdown` 命名。

### 6.2 D1 Schema 草案

```sql
CREATE TABLE IF NOT EXISTS users (
  id TEXT PRIMARY KEY,                       -- Clerk user id
  email TEXT UNIQUE NOT NULL,
  subscription_tier TEXT NOT NULL DEFAULT 'free',
  subscription_status TEXT NOT NULL DEFAULT 'none',
  stripe_customer_id TEXT UNIQUE,
  stripe_subscription_id TEXT UNIQUE,
  stripe_price_id TEXT,
  current_period_end TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS exam_records (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  subject_id TEXT NOT NULL,
  date TEXT NOT NULL,
  mcq_score REAL NOT NULL,
  frq_score REAL NOT NULL,
  total_percent REAL NOT NULL,
  ap_score INTEGER NOT NULL,
  topic_scores_json TEXT NOT NULL DEFAULT '{}',
  notes TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted_at TEXT,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE TABLE IF NOT EXISTS target_scores (
  user_id TEXT NOT NULL,
  subject_id TEXT NOT NULL,
  target_score INTEGER NOT NULL DEFAULT 3,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, subject_id),
  FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE TABLE IF NOT EXISTS stripe_events (
  id TEXT PRIMARY KEY,                       -- Stripe event id
  type TEXT NOT NULL,
  processed_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_exam_records_user_subject
  ON exam_records(user_id, subject_id);

CREATE INDEX IF NOT EXISTS idx_exam_records_user_date
  ON exam_records(user_id, date);

CREATE INDEX IF NOT EXISTS idx_users_stripe_customer
  ON users(stripe_customer_id);
```

### 6.3 数据约束

- `ap_score` 只能是 1-5。
- `target_score` 只能是 1-5。
- `subject_id` 必须存在于 `subjects` 静态配置中。
- `topic_scores_json` 只保存当前科目的 topic id → 0-100 数字。
- 删除记录优先软删除 `deleted_at`，前端默认不展示。

### 6.4 Wrangler D1 绑定

V2 需要在 `wrangler.jsonc` 增加 D1 绑定：

```jsonc
"d1_databases": [
  {
    "binding": "DB",
    "database_name": "apscoretracker-prod",
    "database_id": "..."
  }
]
```

本地开发可使用 Wrangler local D1。迁移脚本建议放在：

```text
migrations/
  0001_v2_core.sql
```

## 7. API Contract

所有业务 API 默认需要 Clerk session。`/api/stripe/webhook` 例外，使用 Stripe signature 鉴权。

### 7.1 `GET /api/me`

返回当前用户、订阅、限制和用量。

```json
{
  "user": {
    "id": "user_...",
    "email": "student@example.com"
  },
  "subscription": {
    "tier": "free",
    "status": "none",
    "currentPeriodEnd": null
  },
  "usage": {
    "subjectsUsed": 2,
    "recordsTotal": 8,
    "recordsBySubject": {
      "ap-lang": 5,
      "ap-psych": 3
    }
  },
  "limits": {
    "subjects": 5,
    "recordsPerSubject": 10,
    "csvExport": false,
    "advancedReport": false
  }
}
```

### 7.2 `GET /api/records?subjectId=ap-lang`

返回当前用户记录，按 `date desc`。

```json
{
  "records": [
    {
      "id": "uuid",
      "subjectId": "ap-lang",
      "date": "2026-06-26T00:00:00.000Z",
      "mcqScore": 35,
      "frqScore": 13,
      "totalPercent": 72,
      "apScore": 4,
      "topicScores": {
        "claims-evidence": 80
      },
      "notes": "Need synthesis practice"
    }
  ]
}
```

### 7.3 `POST /api/records`

请求：

```json
{
  "subjectId": "ap-lang",
  "date": "2026-06-26T00:00:00.000Z",
  "mcqScore": 35,
  "frqScore": 13,
  "topicScores": {
    "claims-evidence": 80
  },
  "notes": "Need synthesis practice"
}
```

服务端职责：

- 校验用户登录。
- 校验 subject、score 范围、topic id。
- 重新计算 `totalPercent` 和 `apScore`，不要信任客户端传入结果。
- 校验 Free/Pro limit。
- 写入 D1。

错误码：

| 状态码 | code | 含义 |
|---:|---|---|
| 401 | `UNAUTHENTICATED` | 未登录 |
| 400 | `INVALID_INPUT` | 输入非法 |
| 403 | `LIMIT_REACHED` | Free 限制触发 |
| 500 | `SERVER_ERROR` | 服务端异常 |

### 7.4 `DELETE /api/records/[id]`

软删除当前用户记录。

### 7.5 `GET /api/targets`

返回当前用户所有目标分数。

```json
{
  "targets": {
    "ap-lang": 4,
    "ap-psych": 5
  }
}
```

### 7.6 `PUT /api/targets`

请求：

```json
{
  "subjectId": "ap-lang",
  "targetScore": 4
}
```

### 7.7 `POST /api/billing/subscribe`

请求：

```json
{
  "plan": "monthly"
}
```

Elements 方案响应：

```json
{
  "mode": "elements",
  "clientSecret": "pi_..._secret_..."
}
```

Checkout 备选响应：

```json
{
  "mode": "checkout",
  "url": "https://checkout.stripe.com/..."
}
```

### 7.8 `POST /api/billing/portal`

返回 Stripe Customer Portal URL。

### 7.9 `POST /api/stripe/webhook`

处理事件：

- `customer.subscription.created`
- `customer.subscription.updated`
- `customer.subscription.deleted`
- `invoice.paid`
- `invoice.payment_failed`
- `checkout.session.completed`，仅 Checkout 备选需要

要求：

- 验证 `stripe-signature`。
- 写入 `stripe_events` 防重复处理。
- webhook 成功后更新 `users.subscription_tier`、`subscription_status`、`current_period_end`。

## 8. 功能需求

### 8.1 P0 — Clerk Auth

需求：

- 集成 Clerk Provider。
- 新增 `/sign-in` 和 `/sign-up`。
- Navigation 显示 Sign In 或用户头像。
- API 路由获取当前 Clerk user。
- 首次登录 upsert D1 `users`。

验收：

- Google OAuth 登录成功。
- Email 登录成功。
- 登出后 session 清除。
- 未登录访问受保护 API 返回 401。

### 8.2 P0 — D1 云端记录

需求：

- 新增 D1 migration。
- 新增 records / targets API。
- TrackerApp 登录后从 API 读写。
- 服务端重新计算分数。
- Free limit 在服务端执行。

验收：

- 保存记录后刷新仍在。
- 同账号跨浏览器同步。
- 不能读写其他用户记录。
- Free limit 无法通过前端绕过。

### 8.3 P0 — Anonymous 体验降级

需求：

- 未登录可以浏览 `/tracker`。
- 未登录可以输入分数并看到即时估分。
- 未登录保存按钮触发登录引导。
- 历史、目标分数、导出区域显示登录提示或示例状态。

验收：

- 未登录用户不会产生 localStorage 新记录。
- 保存、导出、历史入口均引导登录。
- 试算体验仍顺畅。

### 8.4 P0 — Free / Pro 限制

需求：

- Free：每科最多 10 条记录。
- Free：当前 5 个 Tracker 科目可用。
- Pro：不限制记录数。
- 超限时弹 Upsell Modal。
- 权限判断以前端展示 + 服务端强校验双层实现。

验收：

- Free 第 11 条保存失败并提示升级。
- Pro 第 11 条可保存。
- 降级用户保留旧数据，但不能新增超限数据。

### 8.5 P0 — Stripe 订阅

需求：

- 支持 monthly / yearly Pro。
- Stripe Customer 与 Clerk user 绑定。
- Webhook 同步订阅状态。
- 支付成功后前端重新拉取 `/api/me`。
- 用户可进入 Customer Portal 管理订阅。

定价默认值：

| Plan | Price | Price key |
|---|---:|---|
| Pro Monthly | $4.99/month | `NEXT_PUBLIC_STRIPE_PRO_MONTHLY_PRICE_ID` |
| Pro Yearly | $39.99/year | `NEXT_PUBLIC_STRIPE_PRO_YEARLY_PRICE_ID` |

验收：

- Stripe test card 支付成功。
- 3D Secure 流程成功。
- Webhook 收到并更新 Pro。
- 取消订阅后到期降级。
- 付款失败进入 `past_due` 或等价状态。

### 8.6 P1 — Account 页面

需求：

- 展示 email、tier、status、period end。
- 展示 records usage。
- 提供 JSON export。
- Pro 提供 CSV export。
- 提供 Manage Subscription。
- 提供 Delete Account。

验收：

- Free/Pro 展示正确。
- 导出文件字段完整。
- 删除账户二次确认。
- 删除后 D1 数据不可再访问。

### 8.7 P0 — 法务与合规更新

必须更新：

- `/privacy`
- `/terms`
- `docs/compliance-report.md`

新增说明：

- Clerk 处理登录数据。
- Cloudflare D1 存储模考数据。
- Stripe 处理支付数据。
- Plausible 分析脚本。
- 数据导出和删除方式。
- 订阅、取消、退款、降级规则。

  "d1_databases": [

## 11. 安全与合规

### 11.1 安全要求

- 所有业务 API 默认校验 Clerk session。
- Stripe webhook 必须校验签名。
- D1 查询必须参数化。
- 服务端重新计算分数，不信任客户端传入的 `totalPercent`、`apScore`。
- 用户只能访问 `user_id = currentUser.id` 的数据。
- Delete Account 必须二次确认。
- Secret 不进入 `NEXT_PUBLIC_*`。

### 11.2 隐私要求

- 明确列出收集的数据：
  - Email
  - Clerk user id
  - 模考记录
  - topic scores
  - notes
  - billing customer/subscription id
- 明确列出第三方：
  - Clerk
  - Cloudflare
  - Stripe
  - Plausible
- 明确数据保留策略：
  - 用户主动删除账户后删除 D1 数据。
  - Stripe 账单数据按 Stripe/legal 要求保留。
  - soft-deleted records 是否定期清理需拍板。

## 14. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 强制登录降低转化 | 高 | 保留未登录试算，保存时再提示登录 |
| Stripe Elements 订阅复杂 | 中 | Checkout 作为备选方案 |
| D1 schema 返工 | 中 | 先按当前 `ExamRecord` 字段设计，避免旧字段命名 |
| V1 用户 localStorage 数据无法自动迁移 | 中 | 保留 JSON import，自助迁移；自动迁移放 V2.1 |
| Cloudflare Workers 环境差异 | 中 | 每个 milestone 都跑 OpenNext build/preview |
| 合规文档滞后 | 高 | V2 上线前把 privacy/terms/compliance 作为阻塞项 |
| Clerk/Stripe 成本增长 | 低 | 先接受 SaaS 成本，MAU 增长后再评估自建 |
